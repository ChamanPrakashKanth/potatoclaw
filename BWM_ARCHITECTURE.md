# PotatoClaw Bounded Working Memory (BWM) & Hierarchical Memory

## 1. Core Architectural Principle: Selective Retention vs. Naive Summarization

In constrained local models (3B–4B parameters on a 4GB GPU with 2048-token context), unbounded conversation history causes three critical failure modes:
1. **Context Exhaustion**: Trajectories exceed context limits within 3 to 5 multi-step turns.
2. **Attention Dilution / Needle-in-a-Haystack Failure**: 4B models struggle to recall specific instructions buried under thousands of characters of terminal and HTML output.
3. **Inference Latency Bloat**: Autoregressive prompt evaluation slows down proportionally to total tokens, burning battery and GPU thermal headroom.

PotatoClaw replaces raw conversational history with **Bounded Working Memory (BWM)**. The purpose of BWM is **selective retention**, not lossy fuzzy summarization.

---

## 2. Memory Item Data Structure

Each memory item tracked within BWM contains rich metadata for deterministic utility evaluation:

```python
MemoryItem:
    id: str                         # Unique memory identifier (e.g., "fact_042")
    content: str                    # Concise factual statement (<= 140 chars)
    source: str                     # Tool / Verifier / User / System
    timestamp: float                # Creation timestamp
    importance: float               # Intrinsic task weight (0.0 to 1.0)
    goal_relevance: float           # Global relevance to primary objective
    node_relevance: Dict[str, float]# Graph-aware relevance mapped to node IDs
    novelty: float                  # Uniqueness relative to existing memory
    protected: bool                 # Un-evictable flag (True for safety & goals)
    access_count: int               # Number of times accessed / retrieved
    last_access: float              # Last access timestamp
    token_cost: int                 # Estimated token footprint (~chars / 4)
```

---

## 3. Mathematical Scoring Function

To determine which non-protected items remain in the active working memory under a hard budget cap, PotatoClaw evaluates a composite utility score:

$$\text{Score}(m_i, v) = w_1 \cdot \text{Importance} + w_2 \cdot \text{Relevance}(v) + w_3 \cdot \text{Novelty} + w_4 \cdot \text{Recency} - w_5 \cdot \text{Cost}$$

Where:
- **$\text{Importance}$**: Intrinsic weight assigned based on factual criticality ($0.0 \le I \le 1.0$).
- **$\text{Relevance}(v)$**: Node-specific relevance $R(m_i, v)$ if the memory was generated by or attached to node $v$, otherwise defaulting to global goal relevance.
- **$\text{Recency}$**: Exponential decay based on access age:
  $$\text{Recency} = 0.5^{\frac{\Delta t}{300\text{s}}}$$
- **$\text{Novelty}$**: $1.0$ for novel facts, discounted for semantically overlapping entries.
- **$\text{Cost}$**: Normalized token penalty $\frac{\text{token\_cost}}{100}$, penalizing bloated observations.

### Calibrated Weight Defaults:
$$w_1 = 0.30, \quad w_2 = 0.35, \quad w_3 = 0.15, \quad w_4 = 0.15, \quad w_5 = 0.05$$

---

## 4. Protected Memory: Non-Evictable Core

Certain information must **never** be evicted regardless of memory pressure:
1. **Global User Goal**: The root objective requested by the user.
2. **Critical User Constraints**: Safety directives, boundaries, forbidden actions (e.g., *"Do not delete database"*, *"Do not touch production branch"*).
3. **Modified Paths & Irreversible State**: List of created or altered file paths.
4. **Active Unresolved Errors**: Failures that require diagnostic resolution.

Protected items bypass eviction loops and are guaranteed injection into the context compiler.

---

## 5. Graph-Aware Memory Retrieval

A critical innovation in PotatoClaw is **Graph-Aware BWM Retrieval**. Instead of retrieving globally relevant memories for the overarching goal:
$$\text{Memory}_{\text{global}} = \text{TopK}\Big(\text{Relevance}(m_i, \text{Goal})\Big)$$
PotatoClaw conditions retrieval on the **Active Task Graph Node** $v$:
$$\text{Memory}(v) = \text{ProtectedState} \cup \text{TopK}\Big(\text{Score}(m_i, v)\Big)$$

### Concrete Example
- **Current Node**: `"run_parser_tests"`
- **Relevant Memories Retrieved**:
  - `[CRITICAL] Do not modify src/core/api.ts` (Protected Constraint)
  - `Found crash on empty input string at parser.py:42` (Node-relevant)
  - `pytest -k test_parser executed with exit code 1` (Node-relevant)
- **Irrelevant Memories Excluded**:
  - `Browser opened https://news.ycombinator.com 15 minutes ago`
  - `Temporary directory created in /tmp/scratch`
  - `CSS layout styling warning in dashboard`

The 4B model receives high-signal, zero-noise context tailored exclusively to the test execution.

## 6. Hierarchical Memory Tiers: L0, L1, L2

PotatoClaw organizes memory across three computational tiers:

```
┌─────────────────────────────────────────────────────────────┐
│  L0: IMMEDIATE CONTEXT                                      │
│  - Raw tool observation (uncompressed stdout, HTTP body)   │
│  - Kept only during the immediate actuator step             │
│  - Size: 100 - 5,000 bytes (Transient)                      │
└──────────────────────────────┬──────────────────────────────┘
                               │ Observation Compiler
                               ▼
┌─────────────────────────────────────────────────────────────┐
│  L1: BOUNDED WORKING MEMORY (BWM)                           │
│  - Active structured state block                            │
│  - Strict budget: <= 850 characters (~200 tokens)           │
│  - Injected into every model inference turn                 │
└──────────────────────────────┬──────────────────────────────┘
                               │ Milestone Promotion
                               ▼
┌─────────────────────────────────────────────────────────────┐
│  L2: PERSISTENT SEMANTIC STATE                              │
│  - Durable disk/json backed storage                         │
│  - Artifact registry, architectural decisions, checkpoints  │
│  - Preserved across agent crashes and system restarts       │
└─────────────────────────────────────────────────────────────┘
```

By strictly restricting L1 to $\le 850$ characters, prompt context remains rock-solid and context utilization never exceeds 10–25% of the 2048-token limit.
